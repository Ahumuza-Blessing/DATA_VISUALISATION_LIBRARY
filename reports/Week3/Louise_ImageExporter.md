1. Introduction

This report presents the Phase 1 design and implementation of the ImageExporter module for the C++ Data Visualization Library. The purpose of this module is to provide a simple and reliable way of saving graphics generated by the Renderer into SVG files.

The module acts as the final stage of the visualization process. After the Renderer generates SVG content, ImageExporter determines the appropriate output location and saves the content as a file.

2. Objectives

The main objective was to design and implement an ImageExporter module that supports saving SVG graphics to files.

The specific objectives were to:

- Create the ImageExporter header and implementation files.
- Define functions for determining output file locations and saving SVG content.
- Establish a default output directory for generated graphics.
- Support user-specified file paths.
- Automatically create destination directories when they do not exist.
- Include error handling for invalid filenames and file-writing failures.

3. Design of the ImageExporter Module

The module was designed using object-oriented programming principles. A class named "ImageExporter" was created to group the operations responsible for exporting graphics.

The implementation was divided into two files:

3.1 ImageExporter.hpp

The header file contains the class declaration and the function prototypes.

The class provides two public static functions:

- "outputFile(const std::string& filename)": Determines the appropriate location for the output file.
- "saveSVG(const std::string& svg, const std::string& filePath)": Saves the supplied SVG content to the specified file.

The use of static functions allows these operations to be called directly using the class name without creating an ImageExporter object.

3.2 ImageExporter.cpp

The implementation file contains the actual definitions of the two functions. It includes the following standard C++ libraries:

- "<filesystem>" for handling file paths and creating directories.
- "<fstream>" for opening and writing files.
- "<stdexcept>" for handling errors through standard exceptions.

4. Implementation of the Main Functions

4.1 Output File Location Function

The "outputFile()" function determines where a generated SVG file should be stored.

Its main operations include:

1. Checking whether the supplied filename is empty.
2. Creating a filesystem path from the supplied filename.
3. Checking whether the path is absolute or contains a parent directory.
4. Placing a filename without a specified directory inside the default "data/output" folder.
5. Returning the resulting file path as a string.

The implementation also supports a configurable default output directory through the "DATAVIZ_DEFAULT_OUTPUT_DIR" preprocessor definition.

This provides flexibility because the project can change its default output location without changing the function's main implementation.

4.2 SVG Saving Function

The "saveSVG()" function is responsible for writing SVG content into an output file.

Its operation follows these steps:

1. Calls "outputFile()" to determine the destination path.
2. Checks whether the destination has a parent directory.
3. Uses "std::filesystem::create_directories()" to create the required directory if it does not exist.
4. Opens the destination file using "std::ofstream".
5. Writes the SVG content into the file.
6. Checks whether the writing operation was successful.

If the file cannot be opened or writing fails, the function throws a "std::runtime_error".

This approach helps prevent export failures caused by missing destination folders or file-writing problems.

5. Expected Operation of the Module

The ImageExporter module is designed to work with the Renderer in the following sequence:

Renderer → SVG content → ImageExporter → Output file

The Renderer generates SVG markup as a string. ImageExporter receives this string and saves it to the specified location.

For example, when a filename such as "histogram.svg" is supplied without a directory, the module places it in:

"data/output/histogram.svg"

When a directory is explicitly supplied, the function uses that path. Absolute paths are also supported.

This arrangement allows generated visualizations to be organized in a consistent output directory.

6. Object-Oriented Programming Concepts

6.1 Encapsulation

Encapsulation is demonstrated by grouping the file-exporting operations within the "ImageExporter" class.

The functions are declared under the public access specifier, allowing other project components to use the module through its defined interface without directly handling the internal file-writing operations.

6.2 Abstraction

The module provides a simple interface for saving SVG graphics. Other components only need to call "saveSVG()" without managing directory creation, file opening, or writing operations themselves.

This reduces the complexity of using the export functionality.

6.3 Modularity and Reusability

The implementation separates the interface from the function definitions using a header file and a source file.

This makes the module easier to maintain and allows other parts of the C++ Data Visualization Library to reuse its functionality.

7. Error Handling

The implementation handles the following situations:

Empty output filename| Throws "std::invalid_argument"
Failure to open output file| Throws "std::runtime_error"
Failure during writing| Throws "std::runtime_error"

The use of standard exceptions allows other parts of the project to detect and handle export-related errors.
